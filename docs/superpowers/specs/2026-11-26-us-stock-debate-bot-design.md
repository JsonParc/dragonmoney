# JsonParc Stock Bot — 설계 문서

- 작성일: 2026-11-26
- 대상 시장: 미국 주식 (S&P 500 중심)
- 하드 데드라인: **2026-12-22 (사용자 입대일)** — 이날 이전에 서버에서 무인으로 돌아가야 함

---

## 1. 목적과 이유

사용자가 2026-12-22 입대 후 약 1년 반 동안 직접 매매할 수 없는 상황에서, **여러 LLM이 토론해 결정하는 미국 주식 봇**이 서버에서 혼자 돌면서 자산을 불리는 것이 목적이다. 특히 보유 종목에 악재(예: 기술주 보유 중 전쟁 → 유가 폭등)가 터졌을 때 **과거 비슷한 사례의 하락률로 하락폭을 예측하고, 미리 빼서 방어한 뒤 싸게 되사거나, 추가매수/손절/종목교체**를 하는 것이 핵심 차별점이다.

사용자는 군 복무 중 휴대폰을 저녁에만(훈련소 기간엔 아예 못) 쓸 수 있으므로, 봇은 **텔레그램으로 보고하고 승인을 받으며**, 연락이 안 되면 **방어적으로만** 행동해야 한다.

당장은 본인용이고, 잘 되면 GitHub로 지인들에게 배포할 예정이다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 차트팀 vs 뉴스팀 LLM 토론으로 매매 결정, 과반 동의 시에만 실행
- 보유 종목 관련 뉴스 상시 감시 → 악재·호재 시 긴급 토론
- 과거 사건 사례집으로 "이번 사건이면 얼마나 빠질지" 예측
- 2024·2025년 데이터로 빠른 백테스트 + 파라미터 튜닝
- 모의투자 / 실전 모드 전환
- 웹 관리페이지(휴대폰 화면 우선) + 텔레그램 봇으로 보고·승인·제어
- 12/22 이전에 Render 서버에서 무인 운영 시작
- 지인 배포 가능한 형태 (설치 문서, 키 분리, Docker)

**비목표 (지금은 안 함)**
- 한국 주식, 분·초 단위 단타, 옵션/레버리지/공매도
- LLM 자체를 학습(파인튜닝)시키는 것 — "훈련"은 파라미터 튜닝 + 사례집 구축을 뜻함
- 여러 사용자가 한 서버를 같이 쓰는 기능 (지인은 각자 자기 서버/PC에서 실행)

**반목표 (기술적으로 돌아가도 이러면 실패)**
- **말만 잘하는 봇**: 설득 보너스가 결과와 무관하게 쌓여 "센 말"을 하는 AI가 이기는 구조
- **백테스트만 좋은 봇**: LLM이 과거를 이미 알아서, 또는 튜닝 과적합으로 테스트 성적만 좋은 것
- **사용자 모르게 큰돈이 나가는 것**: 승인 없는 신규 매수(자동 모드 OFF일 때), 한도 초과 주문
- **팔 수 없는 종목을 사는 것**: 거래량이 적은 종목 매수
- **API 비용 폭탄**: 1년 반 무인 운영 중 LLM 과금이 통제 없이 쌓이는 것
- **조용히 죽는 봇**: 데이터 소스나 API가 고장 났는데 아무도 모르는 것
- **키 유출**: API 키·증권사 키가 GitHub에 올라가는 것

## 3. 제약

- **시간**: 오늘(11/26)부터 12/22까지 약 26일. 우선순위(§12) 엄수.
- **LLM 사전지식 누출**: LLM은 2024~2026년 사건을 이미 알 수 있다. 백테스트 성적은 실제보다 좋게 나올 수 있으며, 완화(§8.4)는 하되 완전히 없앨 수 없다. 이 한계를 결과 화면에 명시한다.
- **무료 데이터만**: 주가 yfinance, 과거 뉴스 GDELT(2015년 2월~), 실시간 뉴스 RSS·Finnhub 무료 티어. 유료 데이터는 쓰지 않는다.
- **적은 예산**: 백테스트 목표 비용 ≈ $0 (LLM 무료 사용량 + 캐시), 실전 운영 월 상한 기본 $10.
- **입대 후엔 코드 수정 불가**: 실전 전환에 필요한 모든 것(KIS 실전 어댑터 포함)은 12/22 이전에 완성·검증돼 있어야 하고, 실전 전환은 휴대폰만으로 가능해야 한다.
- **서버**: 사용자의 기존 Render 유료 계정에 **새 서비스**로 배포 (SLBM WIKI 서비스와 합치지 않음). 무거운 작업(백테스트·튜닝)은 입대 전 사용자 PC에서 끝낸다.
- **증권사**: 아직 미연결. 실전은 한국투자증권(KIS) 해외주식 Open API를 1순위로 상정. 계좌 개설·API 신청은 사용자가 즉시 진행해야 함.
- **미국장 시간**: 한국시간 23:30~06:00 (서머타임 22:30~05:00). 군 휴대폰 사용 시간(저녁)과 장 시작 전 시간이 겹쳐 승인 흐름에 유리함.

## 4. 접근 방식

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 파이썬 앱 하나 + 웹 관리페이지 + SQLite + Docker** ✅ 채택 | 한 프로세스가 스케줄러·토론·텔레그램·웹을 모두 돌림 | 설치 간단(지인 배포 쉬움), Render 서비스 1개로 운영 가능, 비용 최소 | 대규모 확장엔 부적합 (필요 없음) |
| B. 서비스 분리 (Postgres, Redis, 워커, 별도 프론트) | 마이크로서비스 | 확장성 | 설치·운영 난이도 큼, 서버 비용 증가, 26일 내 완성 어려움 |
| C. Streamlit 같은 대시보드 도구 | 빠른 화면 | 초기 속도 | 상시 운영 봇·실전 주문·텔레그램 연동에 약함, 결국 재작성 |

A를 채택한 이유: 사용자 목표(무인 운영 + 지인 배포)와 26일 일정에 가장 맞고, Render 서비스 하나로 비용이 가장 적다.

## 5. 사용자가 정한 사항

1. **시장**: 미국.
2. **팀 구성**: 차트팀 vs 뉴스팀 **5:5(동일 비중)**. 홀수 인원으로 한쪽이 유리해지는 구조는 거부.
3. **순수 차트 AI**: 인터넷에 떠도는 기술적 분석 스타일 — 이평선 골든/데드크로스, 정배열, "세력 들어왔다"(거래량 급증) 등 **차트 모양만** 보고 판단.
4. **사례참고 AI**: 차트 유사도가 아니라 **뉴스 기반의 확장** — "과거 비슷한 사건이 터졌을 때 이 업종/종목이 얼마나, 며칠 빠지고 언제 회복했나".
5. **답 강제**: 어느 쪽도 결론을 못 내면(교착) **양 팀 모두 패널티**. "모르겠다" 불허.
6. **설득 보너스**: 상대를 설득한 쪽에 보너스. 단 **설득한 결정이 실제로 맞았을 때만** 지급, 틀렸으면 감점 (B안).
7. **실행 모드**: 기본은 **반자동(B)** — 방어적 매도는 자동, 신규/추가 매수는 승인 필요. **자동 모드(완전 자동)는 사용자가 원할 때 켜고 끌 수 있음.**
8. **텔레그램 봇**으로 휴대폰 명령·승인.
9. **매일 보고서 + 투자 설명회**: 뉴스·전날 시장상황·최근 동향과 판단을 요약한 보고서를 발행하고, 사용자를 대상으로 투자 설명회를 진행.
10. **유동성 규칙**: 거래량 일정 이하 종목은 **절대 매수 금지** (사기는 쉬워도 팔기 어려움).
11. **운영 위치**: 지금은 사용자 PC에서 개발·테스트, 입대 전 서버로 이전.
12. **테스트/훈련 기간**: 테스트는 작년·재작년(2024, 2025), 훈련은 최근 약 10년(뉴스 포함).
13. **비용**: 여유자금이 적음. **뉴스는 무료 소스만**. 백테스트·운영 모두 비용 최소화가 최우선.
14. **오픈소스 참고 도구는 최대한 투입** (§7.13).
15. **훈련소 기간 = 모의투자**: 12/22부터 훈련소 기간 동안 모의투자로 운영해 실력을 검증. 결과가 괜찮으면 그동안 모은 돈으로 실전 시작. 현재 실전에 넣을 돈은 없음.
16. **긴급 정지 대리인 없음**: 텔레그램 명령 + **봇이 만질 수 있는 금액을 사용자가 정하는 것**으로 충분하다고 판단.
17. **뉴스는 최대한 여러 곳에서 수집하고, 뉴스끼리 대조해 가짜인지 확인** (§7.1a).
18. **모의/실전 각각 매수 허용 상품 옵션** (2026-11-26 추가): ETF 허용, 레버리지·인버스 ETF(SOXL·TQQQ·SQQQ 등) 허용, 거래량 적은 종목 허용(거래대금 하한 해제, 주문량 ≤ 평균 거래량 1% 규칙은 유지). 기본은 모두 꺼짐. 실전 옵션 변경은 PIN 필요. 차입(신용) 레버리지는 다루지 않음.
19. **재무제표 분석가 추가** (2026-11-27): 뉴스팀에 재무 분석가(PER·PSR·PBR·성장률·마진·ROE·부채비율·배당; Finnhub 기본 재무지표 → 야후 대체, 하루 캐시), 팀 균형을 위해 차트팀에 보조지표 차트쟁이(MACD·볼린저) 추가 → 4:4, 정족수 5석. 현재 지표라 백테스트 as-of에는 쓰지 않음(Plan 2에서 SEC 공시 기준으로).

## 7. 구성 요소 상세

### 7.1 데이터 계층

- **주가**: yfinance 일봉, 2014년~현재. S&P 500 구성종목 + 섹터 ETF(XLK, XLE 등 11개) + SPY/QQQ.
  - 생존 편향 방지: 과거 시점의 S&P 500 구성종목 이력을 사용 (공개된 이력 데이터셋 활용, 구체 소스는 빌더 결정).
- **거시**: 유가(CL=F), 미 10년물(^TNX), 달러인덱스(DX-Y.NYB), VIX(^VIX), 금(GC=F), 원달러.
- **과거 뉴스**: GDELT (2015-02~). 이벤트 테이블(지정학·분쟁 코드)과 GKG(기업·주제 태그)를 사용.
  - ⚠️ 종목 단위 과거 뉴스(2024~2025 백테스트용) 확보 방법은 **첫 번째 스파이크 작업**으로 검증 (§12).
- **실시간 시세 (서버)**: yfinance는 클라우드 서버에서 자주 차단되므로 서버 운영 시에는 쓰지 않는다. 실전 모드에서는 KIS 시세, 모의 모드에서는 Finnhub 무료 시세(분당 60회)를 1순위로, 다른 무료 소스를 예비로 둔다. 시세가 끊기면 방어 모드 + 알림. yfinance는 PC에서 과거 데이터 수집용으로만 사용 — *내 판단*
- **실시간 뉴스**: 주요 경제지 RSS + Finnhub 무료 API(기업 뉴스) + GDELT 최신 피드.
- **뉴스는 최대한 여러 곳에서 수집** (사용자 지시): 주요 경제지·방송사 RSS 다수(CNBC, MarketWatch, Yahoo Finance, Nasdaq, Investing.com, BBC/CNN 비즈니스 등), Google News RSS(종목·키워드 검색), Finnhub, GDELT(전 세계 수천 개 매체 집계), **1차 출처**(SEC EDGAR 공시 8-K 등, 연준·노동통계국 보도자료). 소스 목록은 설정 파일로 관리해 추가·삭제 가능.

#### 7.1a 뉴스 교차검증 (가짜·루머 거르기)

사용자 지시: 뉴스끼리 대조해서 가짜인지 확인한다.
- **같은 사건 묶기**: 시간 창(기본 24시간) 안에서 제목·요약 유사도(임베딩, 없으면 단어 겹침)로 같은 사건을 다룬 기사를 하나의 묶음(클러스터)으로 만든다.
- **독립 출처 수 세기**: 같은 통신사 기사를 여러 매체가 그대로 받아쓴 경우(본문 거의 동일, 같은 통신사 표기)는 1개로 센다. 출처는 도메인 단위로 구분한다.
- **출처 신뢰 등급**: 0등급 = 1차 출처(SEC 공시, 연준, 정부 통계, 회사 IR), 1등급 = 주요 통신사·경제지, 2등급 = 일반 매체, 3등급 = 블로그·커뮤니티·출처 불명. 등급표는 설정 파일.
- **검증 상태**
  - `확인됨`: 0등급 1개 이상, 또는 1~2등급 독립 출처 2개 이상
  - `미확인`: 위 조건 미달 (단일 출처, 3등급만 등)
  - `반박됨`: 같은 묶음에 "부인", "사실무근", "루머", "denies", "false report" 등 반박 기사가 0~1등급에서 나옴
- **행동 규칙**
  - 긴급 토론과 자동 방어 매도는 **`확인됨` 뉴스로만** 발동
  - `미확인`인데 심각도가 높으면: 텔레그램으로 "확인 중" 알림만 보내고, 다음 폴링마다 다시 대조. 확인되면 그때 긴급 토론
  - `반박됨`은 토론 자료에서 제외하고, 반박 사실 자체를 뉴스팀에 알려준다 (루머로 생긴 급락은 되사기 기회가 될 수 있음)
  - 토론에 넘기는 뉴스 요약에는 검증 상태와 독립 출처 수를 함께 표시 (예: "[확인됨·출처 5곳] …")
- 백테스트에서도 같은 규칙을 적용한다 (GDELT는 매체가 많아 대조에 유리).
- 모든 데이터는 **시점 기준(as-of)** 으로 저장·조회한다. 백테스트에서 그날 이후 데이터가 절대 섞이지 않도록 조회 함수가 날짜를 강제한다.

### 7.2 차트 규칙 엔진 (코드)

LLM에 넘기기 전에 코드가 계산하는 지표·패턴:
- 이동평균 5/20/60/120일, 골든/데드크로스, 정배열/역배열
- RSI, MACD, 볼린저밴드, OBV
- 거래량 비율(20일 평균 대비), **"세력 매집" 휴리스틱**(횡보 중 거래량 증가 + OBV 상승), 장대양봉/음봉, 윗꼬리/아랫꼬리, 눌림목, 박스권 돌파, 지지/저항선
- 결과는 "20일선 돌파 + 거래량 4.1배 + 윗꼬리 없음" 같은 **사람이 읽는 문장 목록**과 수치로 정리
- **차트 이미지**(최근 6개월 캔들 + 이평선 + 거래량, mplfinance)를 생성해 차트팀에 함께 전달

### 7.3 사건 사례집 (Case Library) — "훈련"의 핵심

- **사건 추출**: 2015~2023년 뉴스에서 시장에 영향을 준 사건을 추출하고 유형으로 분류.
  - 유형 예: 전쟁/지정학, 유가 충격, 금리 인상/인하, 물가지표 쇼크, 팬데믹, 은행 위기, 관세/무역분쟁, 규제, 공급망, 실적 쇼크, 대형 기업 이슈.
  - 방법: GDELT 이벤트 급증 + LLM 분류로 후보를 만들고, 주요 사건 목록(LLM이 초안 작성)과 교차 확인. 사건마다 날짜·유형·심각도·설명·관련 업종.
- **반응 통계** (가격 데이터로 계산 — 비용 없음): 각 사건에 대해 섹터 ETF와 종목별
  - D+1, D+5, D+20 수익률, 최대 낙폭, 바닥까지 걸린 일수, 회복까지 걸린 일수
  - 그 당시 시장 상황(VIX 수준, 추세)도 함께 저장
- **조회**: 새 뉴스가 들어오면 유형 + 설명 임베딩 유사도 + 시장 상황 유사도로 과거 사례 상위 K개를 찾고 통계를 요약.
  - 출력 예: "유사 사례 7건, 기술주 섹터 D+5 평균 -6.2%(최악 -11%), 바닥까지 평균 4일, 회복 평균 23일"
- 사례참고 AI는 이 결과를 해석해 의견을 낸다. 하락 예측가와 재매수 목표가 산출의 근거가 된다.
- 실시간 운영 중 새 사건도 사례집에 계속 추가한다.

### 7.4 1차 필터 (비용 절감)

매일 전 종목에 토론을 돌리면 비용이 폭발하므로, 코드로 먼저 거른다:
- 토론 대상 = **신호가 있는 보유 종목**(급등락, 악재 뉴스, 손절선 근접 등) + **신규 후보 상위 N개**(기본 5개, 차트 신호·뉴스 모멘텀 점수 기준)
- **유동성 필터 통과 종목만 신규 후보가 될 수 있음** (§7.7)
- 신호 없는 날은 토론 없이 넘어감

### 7.5 토론 엔진

**참가자**
- **차트팀 (기본 3석)**: ① 이평·추세 ② 거래량·세력 ③ 캔들·패턴 — 모두 "차트 모양만" 보는 차트쟁이
- **뉴스팀 (기본 3석)**: ① 뉴스 AI ② 사례참고 AI ③ 거시경제 AI(유가·금리·환율·지수)
- **심판 (투표권 없음)**: 리스크관리 관점에서 토론을 진행하고, 진영 변경(설득) 여부를 기록하고, 합의된 세부안(수량·가격)을 정리
- 좌석 수는 설정 가능하되 **양 팀 동일 인원** 강제
- 좌석마다 LLM 회사·모델 배정. **기본값은 무료 사용량이 있는 제공자 우선** (Gemini API 무료 티어, Groq 무료 티어의 오픈 모델 등), 유료 키(Claude, GPT 등)가 있으면 추가. 키가 없거나 한도 초과인 좌석은 다른 모델로 대체. 같은 팀 안에서도 제공자를 섞는 것을 기본값으로 함 (생각 쏠림 방지)
- 무료 티어는 입력이 제공자 학습에 쓰일 수 있으므로 **계좌·키·개인정보는 절대 프롬프트에 넣지 않는다** (시장 데이터만)
- 입력은 짧고 구조화된 요약으로 압축해 토큰을 아낀다 (원문 뉴스 대신 FinBERT로 거른 요약, 지표는 문장 목록)

**안건 (행동 종류)**
- 매수 쪽: `BUY`(신규), `ADD`(추가매수)
- 유지: `HOLD`
- 매도 쪽: `TRIM`(일부 매도), `SELL`(전량 매도/손절), `SELL_REBUY`(지금 팔고 목표가에 되사기), `SWITCH`(팔고 다른 종목 매수)

**의견 형식 (구조화 JSON 강제)**: 행동, 확신도(0~1), 비중/수량 제안, 예상 하락률·목표가·재매수가, 기간, 근거(인용한 지표/뉴스/사례 ID). 형식 위반·무응답 시 1회 재요청, 그래도 실패하면 해당 좌석 **개인 패널티** + 이번 투표 기권 처리.

**흐름**
1. 라운드 0: 6명이 각자 의견 제출 (같은 팀 의견은 서로 볼 수 있음)
2. 팀 입장 = 팀원 가중 다수결
3. 두 팀 입장이 같으면 → 바로 리스크 규칙으로
4. 다르면 → 반박 라운드 최대 N회(기본 2): 모든 참가자가 상대 팀 근거를 보고 입장 유지 또는 변경
5. 최종 집계는 2단계:
   - **방향 투표**: 매수 쪽 / 유지 / 매도 쪽 중 **가중치 합 > 50%** 인 방향이 승리
   - **세부안**: 승리 방향 안에서 가장 많은 가중치를 받은 행동, 수량·가격은 승리 측 제안의 가중 중앙값
6. 어느 방향도 50%를 넘지 못하면 → **교착: 양 팀 패널티**, 신규 거래 없음(유지). 단 리스크 규칙의 강제 손절은 별개로 동작.
7. 라운드 0에서 상대 팀 입장이었다가 최종에 진영을 바꾼 참가자가 있으면, 최종 입장을 낸 팀이 **"설득 성공"** 으로 기록 (보너스는 채점 때 결정)

### 7.6 점수판과 가중치 (B안: 결과로 검증)

- **채점 시점**: 결정 후 N 거래일(기본 5일, 설정 가능 5/20)
- **정답 판정**: 실행한 행동의 결과와, 졌던 쪽 행동을 했을 때의 결과(가상)를 비교. 예: 매도 결정 후 주가가 내렸으면 정답, 올랐으면 오답. 차이가 미미하면(임계값 이하) 무승부.
- **점수 규칙 (기본값, 튜닝 대상)**
  - 개인 정확도: 정답 +1 / 오답 −1
  - 설득 성공 + 정답 → 설득한 팀 전원 +보너스(기본 +2)
  - 설득 성공 + 오답 → 설득한 팀 전원 −패널티(기본 −2)
  - 교착 → 양 팀 전원 −1
  - 형식 위반·무응답 → 해당 좌석 −1
- **가중치**: 좌석별 점수의 지수이동평균으로 계산, 범위 **0.5~1.5배**로 제한. 기준선은 양 팀 5:5이고, 성적에 따라 그 범위 안에서 기울어짐.
- **점수판 공개**: 매 토론 프롬프트에 현재 점수·가중치·최근 적중률을 넣어 AI가 의식하게 함.

### 7.7 리스크 규칙 (코드, LLM보다 우선)

LLM이 무슨 결정을 내려도 아래가 우선한다. 모든 값은 설정 가능.
- **유동성 (기본 규칙, '거래량 적은 종목 허용' 옵션으로 하한만 해제 가능)**: 20일 평균 거래대금이 기준(기본 $50M/일) 미만이거나, 주문 수량이 20일 평균 거래량의 1%를 넘으면 **매수 불가**. `ADD`, `SWITCH` 대상에도 적용.
- 총 투입금 상한 (봇이 굴릴 수 있는 최대 금액)
- 종목당 최대 비중(기본 20%), 최대 보유 종목 수(기본 8)
- 강제 손절선(기본 −15%) — 토론 결과와 무관하게 발동
- **누적 손실 서킷브레이커**: 고점 대비 −20%면 신규 매수 전면 중단 + 텔레그램 긴급 알림, 사용자 해제 전까지 유지
- 하루 최대 주문 수·금액
- 레버리지·공매도·옵션 불가

### 7.8 실행 모드와 승인 흐름

**모드는 두 축으로 나뉜다**
- **브로커**: `모의`(내장 모의투자 엔진) / `실전`(KIS 연결)
- **자동화**: `반자동`(기본) / `자동` — 텔레그램과 웹에서 켜고 끌 수 있음

**반자동에서 하는 것**
- 자동 실행: `TRIM`, `SELL`, `SELL_REBUY`의 매도, 강제 손절
- 승인 필요: `BUY`, `ADD`, `SWITCH`의 매수
- `SELL_REBUY`의 되사기: 판 수량 이내에서 같은 종목을 되사는 것은 포지션 복구로 보고 **자동 허용** (설정으로 끌 수 있음) — *내 판단, 확인 필요*
- 승인이 없으면 만료 → 사지 않음

**운영 단계 (사용자 결정)**
| 기간 | 브로커 | 자동화 | 이유 |
|---|---|---|---|
| ~12/21 (입대 전) | 모의 | 반자동 | 사용자가 직접 승인 흐름을 써보며 점검 |
| 12/22~훈련소 수료 | **모의** | **자동** | 승인할 수 없는 기간이므로, 의미 있는 검증 결과를 얻으려면 자동이어야 함 — *자동 설정은 내 판단* |
| 수료 후 | 모의 → (결과 괜찮으면) **실전** | 반자동 기본, 자동은 선택 | 사용자가 휴대폰으로 모의 성적을 보고 직접 전환 |

**휴대폰만으로 실전 전환** (입대 후 코드 수정 불가 대비):
1. 관리페이지 설정에서 KIS 실전 App Key/Secret·계좌번호 입력 (서버 DB에 암호화 저장, 화면엔 다시 표시 안 함)
2. 연결 테스트 버튼 → 잔고 조회 성공 확인
3. 투입금 한도 설정 (계좌 잔고와 한도 중 작은 값까지만 사용)
4. 텔레그램 `/mode real` + PIN → 확인 메시지 후 전환
- 모의 → 실전 전환 시 모의 포지션은 그대로 넘기지 않고, 실전은 현금 상태에서 시작

**하루 일정 (한국시간, 서머타임 시 1시간 당김)**
| 시각 | 할 일 |
|---|---|
| 06:30 | 미국장 마감 후 데이터 수집 → 1차 필터 → 정기 토론 |
| 17:30 | **일일 보고서 + 투자 설명회** 텔레그램 발송, 승인 대기 시작 |
| 23:00 | 장 시작 전 재점검: 밤사이 뉴스·프리마켓 급변 시 재토론 후 알림 |
| 23:30 | 승인된 주문 + 자동 주문 실행, 미승인 건 만료 |
| 장중 | 보유 종목 뉴스 10분 간격 감시 → 심각도 기준 초과 시 긴급 토론 → 방어 행동 자동 실행 + 알림 |

### 7.9 텔레그램 봇

- **보안**: 허용된 chat ID만 응답. 자동 모드 ON, 실전 전환, 서킷브레이커 해제는 **PIN 재입력** 필요.
- 긴급 정지 대리인은 두지 않음 (사용자 결정). 대신 §7.12의 자동 정지 조건과 투입금 한도로 보호.
- **명령**
  - `/report` 오늘 보고서 다시 보기, `/status` 자산·모드·건강상태
  - `/positions` 보유 종목, `/pending` 승인 대기 목록
  - 승인 대기 메시지마다 인라인 버튼 **[승인] [거절] [자세히]**
  - `/auto on|off` 자동 모드 전환, `/pause` `/resume` 신규 매매 일시정지/재개
  - `/stop` 긴급 정지 (신규 주문 전면 중단, 보유는 유지). `/liquidate`는 별도 확인 후 전량 매도
  - `/mode paper|real` 브로커 전환(PIN), `/budget <금액>` 투입금 한도 변경(PIN)
  - `/cost` 이번 달 API 비용, `/ask <질문>` 또는 그냥 질문
- **투자 설명회**: 일일 보고서는 ① 전날 시장 요약 ② 주요 뉴스와 영향 ③ 최근 동향 ④ 보유 종목 점검 ⑤ 오늘의 제안(토론 결과, 찬반 근거, 표결, 예상 시나리오) 순서. 보고서 뒤에 사용자가 질문하면 **그날 토론 기록과 데이터를 바탕으로 답하는 Q&A**를 연다. "설명회"를 이 Q&A까지로 해석함 — *내 판단*.

  ```
  └────────────────────────────────────┘
  ```
  - 대시보드 / 토론 기록(라운드별 발언·표결·설득 여부) / 점수판(좌석별 가중치 추이) / 뉴스 감시 피드(심각도) / 사례집 검색 / 백테스트(실행·진행률·결과 비교) / 설정(좌석-모델 배정, 리스크 값, 모드, 키 상태) / 비용·로그
- 백엔드 FastAPI, 프론트는 React(Vite) 빌드 결과를 FastAPI가 정적 서빙 (서비스 1개 유지)

### 7.11 브로커 연결부

- 공통 인터페이스: 시세 조회, 주문, 체결 조회, 보유·현금 조회
- **모의 브로커(내장)**: 다음 시가 체결 + 슬리피지(기본 5bp) + 수수료. 백테스트와 실시간 모의가 같은 엔진 사용
- **KIS 해외주식 어댑터**: **12/22 이전 완성 필수** (입대 후 수정 불가). KIS 모의투자 계좌로 주문·체결·잔고 조회를 끝까지 검증. 토큰 갱신, 주문 가능시간, 환전/통합증거금 처리는 빌더가 KIS 문서 기준으로 결정
- 훈련소 기간 모의 운영은 내장 모의 브로커로 돌리고, KIS 모의 어댑터는 같은 주문을 병행 전송해 어댑터가 1년 반 동안 계속 작동하는지 확인 (KIS 모의가 미국 주식을 제대로 지원하지 않으면 연결 확인만) — *내 판단, 스파이크로 확인*
- 실전 모드는 어댑터 설정과 연결 테스트를 통과해야만 켤 수 있음
- **소액 대응**: 투입금 대비 1주 가격이 종목당 비중 한도를 넘는 종목은 후보에서 제외. 소수점 매매는 KIS API가 지원하면 사용, 아니면 정수 주만 — *내 판단*
- 권장 운영: **증권 계좌에는 봇이 굴릴 돈만 넣어둔다** (API 키는 계좌 전체를 거래할 수 있으므로, 계좌 잔고 자체를 물리적 한도로 사용)

### 7.12 무인 운영 안전장치

- **건강 점검**: 데이터 수집·LLM 호출·브로커 연결·스케줄 실행을 매 작업마다 기록. 실패가 이어지면 신규 매수 중단(방어 모드) + 텔레그램 알림
- **하트비트**: 매일 보고서 자체가 생존 신호. 추가로 주 1회 "봇 상태 요약" 발송
- **API 비용 상한**: 월 상한(기본 $10, 설정 가능). 무료 사용량을 먼저 쓰고, 유료 호출은 상한 안에서만. 80% 도달 시 알림, 100% 도달 시 무료 모델만 사용, 무료 한도도 소진되면 토론 중단(방어 모드)
- **자동 정지 조건** (대리인 대신): 아래 중 하나라도 걸리면 신규 매수 중단 + 알림, `/resume` 전까지 유지
  - 하루 주문 수·금액이 한도 초과
  - 같은 종목을 짧은 기간에 반복 매매(예: 5거래일 내 3회 이상 왕복)
  - 연속 손실 N회
  - 시세가 비정상(0, 급격한 점프, 오래된 값)이거나 데이터 소스 장애
  - 브로커 잔고와 봇 장부 불일치
- **백업**: SQLite DB를 매일 서버 디스크에 스냅샷, 주 1회 텔레그램으로 파일 전송
- **크래시 복구**: Render 자동 재시작 + 재시작 시 미처리 작업 복구(멱등 처리, 주문 중복 방지)
- **의존성 고정**: 1년 반 무인 운영 중 라이브러리 업데이트로 깨지지 않도록 모든 패키지 버전 고정 (Docker 이미지 기준)

### 7.13 참고·투입할 오픈소스 (사용자 지시: 최대한 투입)

**직접 사용 (비용·시간 절감)**
- **FinBERT** (ProsusAI/finbert): 금융 뉴스 호재/악재 판정. 로컬(CPU)에서 무료로 돌려 뉴스 1차 분류·필터에 사용 → LLM 호출 대폭 감소
- 문장 임베딩 소형 모델 (sentence-transformers 계열): 사례집 유사 사건 검색에 무료 로컬 사용
- 기술적 지표 라이브러리 (pandas 기반), mplfinance (차트 이미지), GDELT 처리 라이브러리
- python-telegram-bot, APScheduler 등 §9 스택

**구조·프롬프트 참고 (코드를 그대로 쓰지 않음)**
- **TradingAgents** (TauricResearch): 분석가 역할 분담 + 강세/약세 토론 + 리스크 관리 구조. 역할 프롬프트와 토론 진행 방식 참고. 우리 규칙(팀 점수판, 결과 검증 설득 보너스)이 없으므로 의존성으로 넣지는 않음
- **FinGPT** (AI4Finance): 금융 뉴스 분석 프롬프트·데이터 처리 방식 참고
- **FinRL** (AI4Finance): 백테스트 평가 지표·비교 기준 구성 참고
- KIS 공식 샘플 코드 (koreainvestment/open-trading-api): 어댑터 구현 시 인증·주문 처리 참고

선정 기준: 실제로 비용이나 개발 시간을 줄이는 것만 넣고, 넣은 것은 버전 고정. 라이선스가 배포(지인 공유)에 문제없는지 확인 — 빌더 확인 사항.

## 8. 백테스트와 튜닝

### 8.1 기간
- **훈련 (사례집 구축 + 파라미터 사전값)**: 2015~2023 (GDELT 시작 시점 때문에 뉴스는 2015-02부터, 가격은 2014부터)
- **테스트 + 튜닝**: 2024, 2025 (사용자 지시)
- **최종 확인 (추가 제안)**: 2026-01~현재. 2024·2025로 튜닝하면 그 기간에 과적합되므로, 손대지 않은 2026년 구간으로 마지막 확인 — *내 판단*

- **실전 전환의 진짜 관문은 백테스트가 아니라 훈련소 기간 모의 운영 성적**이다 (사용자 결정). 백테스트는 파라미터를 맞추고 출발점을 정하는 용도. 관리페이지와 수료 후 보고서에 모의 성적 vs SPY vs 규칙만 버전 비교를 보여줘 사용자가 판단하게 한다.

### 8.2 빠르게 돌리는 방법 — LLM 응답 재생
- 모든 LLM 호출은 (프롬프트 해시, 모델) 기준으로 캐시에 저장
- 가중치·보너스/패널티·임계값·리스크 값 같은 **숫자 파라미터 튜닝은 캐시된 의견으로 재시뮬레이션** → LLM 추가 호출 없이 수백 번 반복 가능
- 프롬프트나 모델을 바꿀 때만 새로 호출
- 실행 전 예상 호출 수·비용을 보여주고 예산 상한 적용
- **비용 ≈ $0 목표**: 무료 티어 모델만으로 실행, 제공자별 속도 제한에 맞춰 호출을 분산·대기. 속도 제한 때문에 2년치 1회 실행이 하루 이상 걸릴 수 있음 (PC에서 밤새 돌리는 것을 상정). 중단돼도 캐시 덕분에 이어서 실행
- 토론은 매일이 아니라 **신호 있는 날 + 큰 뉴스 있는 날**에만. 반박 라운드는 백테스트에서 기본 1회
- 누출 비교(§8.4 가린/안 가린 버전)는 전체가 아니라 표본 구간에서만 실행해 호출 수 절감

### 8.3 튜닝 대상
가중치 범위·속도, 보너스/패널티 크기, 채점 기간, 1차 필터 기준, 뉴스 심각도 임계값, 재매수 할인율, 손절선, 비중 한도. 목표 지표는 **위험조정수익(샤프·최대낙폭)**, 단순 수익률이 아님.

### 8.4 LLM 사전지식 누출 완화
- 백테스트 프롬프트에서 **종목명·날짜를 가림**(예: "종목 A, 대형 기술주", "D일")
- 뉴스 본문의 회사명·날짜 표현도 치환
- 가린 버전과 안 가린 버전 성적을 비교해 누출 정도를 보고서에 표시
- 결과 화면에 "LLM 사전지식으로 실제보다 좋게 나올 수 있음" 경고 상시 표시

### 8.5 비교 기준
SPY 단순 보유, 차트팀만, 뉴스팀만, 토론 없이 규칙만. 토론 구조가 이것들보다 나은지 확인.

## 9. 기술 스택 (빌더 확정 가능)

Python 3.11+, FastAPI, SQLAlchemy + SQLite, APScheduler, pandas, yfinance, mplfinance, httpx, python-telegram-bot, transformers(FinBERT) + sentence-transformers(CPU), 각 LLM 공식 SDK(얇은 공통 어댑터), React + Vite + 차트 라이브러리. 서버 메모리가 작으면 FinBERT는 경량화(ONNX 등)하거나 PC 전용으로 두고 서버는 키워드+LLM 저가 모델로 대체 — 빌더 판단. 로컬은 venv + `start.bat`, 서버는 Docker + `render.yaml`(Render Starter + 영구 디스크).
